# Remaining review findings

- **Custom endpoints:** Carry endpoint context into returned documents before promising custom-host support for model URL properties and search-hit conversion. The current limitation is documented in the [README](README.md#configuration).
- **Incomplete features:** Decide whether to implement or deprecate the `ScraperInfo.from_status_line()` placeholder and inactive `cache_dir` interface; neither is an implemented feature.
- **Response contracts:** Nested search `_source` and index/job data remain partly open-ended. For example, `hierarchy: null` can fail when accessing `SearchHit.spider`, and malformed index change lists can be interpreted incorrectly. Validate these with representative API fixtures; confirm the documented Jobs shape against the service before release. No live service calls were made during this review.
- **Repeated downloads:** With the default formats and successful requests, downloading one document fetches metadata three times. Reuse metadata within each operation, preserving the existing behavior of skipping 404s for every format, including JSON. Responses are buffered entirely in memory; assess streaming and size limits before supporting large downloads.
- **Automation:** Dependabot configuration has been added but remote activation is unverified. There is no checked-in CI workflow or pre-commit setup. Adding pre-commit requires dependency approval; any future workflow actions must use full commit SHAs.
